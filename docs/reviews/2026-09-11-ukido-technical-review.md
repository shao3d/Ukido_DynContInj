## 1. Контекст и как читать документ

### 1.1 Что это за продукт

FastAPI-чатбот для детской школы soft skills «Ukido». Отвечает на вопросы
родителей по курируемой базе знаний (14 markdown-документов), ведёт короткую
историю диалога, адаптирует тон по «сигналу» пользователя
(`price_sensitive`, `anxiety_about_child`, `ready_to_buy`, `exploring_only`),
вставляет CTA и отправляет заявки на пробный урок в HubSpot.

### 1.2 Пайплайн

```
/chat
  └─ main.py: валидация → rate limit → языковая сессия
       ├─ Router (Gemini 2.5 Flash, через OpenRouter)     → классификация,
       │     статус, документы, декомпозиция вопросов, user_signal, язык
       ├─ детерминированные гардрейлы (social / CTA / completed actions)
       ├─ ResponseGenerator (Gemini)                       → ответ по фактам
       ├─ translator.translate() если язык ≠ ru            → 2-й LLM-вызов
       └─ финальный «языковой шлюз» + сохранение состояния
```

Заявленный принцип: «непредсказуемый LLM ограничен алгоритмическими
гардрейлами на Python». Для MVP это разумно и местами реализовано хорошо
(детерминированные social/CTA-правила, изоляция HubSpot, файловая
персистентность, аккуратный деплой). Ниже — где принцип нарушается.

### 1.3 Языки

Поддерживаются **три языка: `ru`, `uk`, `en`.**

- `ru` — первый класс.
- `en` — почти первый класс (словари + защита «EN не видит кириллицу»).
- `uk` — **второй сорт**: словарей нет, всё идёт через машинный перевод с
  русского, а часть пост-обработки вставляет русские фразы уже после перевода.

Это ключевой вывод для цели «все языки должны звучать максимально естественно».

## 3. Краткое резюме для аналитика (Executive summary)

1. **Безопасность.** Чтение произвольных файлов через имена документов от LLM
   (path traversal — закрыт); широкая поверхность prompt-injection (сужена в
   SEC-02: JSON-схема роутера + обёртка текста); сырой HTML и произвольные
   ссылки в ответе API; злоупотребления без лимитов (закрыто в SEC-05:
   лимиты по IP, глобальный бюджет, самоочистка).
2. **Доверие к боту.** Бот уверенно сообщает родителю неверное: «я **не**
   оплатил» → «оплата обрабатывается»; «записались в бассейн» → «запись в
   Ukido». Репутационный риск выше любого технического.
3. **Язык.** Схема «генерация по-русски → перевод» ломает естественность и
   оставляет русские вкрапления в `uk`/`en`. UK без словарей и с ненадёжной
   детекцией; юмор доступен только по-русски.
4. **Продажи.** Блокировка CTA может стать бессрочной; лимиты частоты
   сбрасываются после рестарта; примеры CTA противоречат базе знаний; часть
   CTA-веток недостижима.
5. **Экономика.** Роутер шлёт ~64 KB промпта на каждое сообщение, «кэш»
   фиктивный; один ход — до 4-5 последовательных LLM-вызовов; стриминг
   фейковый.
6. **Надёжность.** Неатомарная персистентность, потеря метаданных, тихая
   очистка повреждённых файлов, `/clear_history` не удаляет данные, откат
   релиза не откатывает зависимости, healthcheck слепой.
7. **Срочность.** `google/gemini-2.5-flash` снимается с Vertex AI
   **16.10.2026**, live-вариант native audio — **13.12.2026**. Миграцию
   планировать сейчас.
8. **Голос.** Единственная крупная продуктовая фича, которой нет. Бюджетный
   путь (голосовые заметки, ~$11-40/мес на 500 сессий) и более дорогой
   (дуплекс realtime, ~$30-75/мес) — см. §12.

## 4. P0 — критично (безопасность и доверие)

### SEC-01 — Path traversal при загрузке документов ✅

**Где:**
- `src/response_generator.py:291-303` — `_load_doc()` делает
  `path = self.docs_dir / doc_name` без проверки, что результат остаётся внутри
  `docs_dir`.
- `src/router.py:279-304` — список `documents` приходит от LLM и не
  валидируется по реальным ключам `data/summaries.json`.

**Суть:** LLM/инъекция может вернуть `../../.env.production` — файл будет
прочитан и вставлен в системный промпт генератора
(`response_generator.py:449-462`), после чего может быть пересказан
пользователю. Путь эксфильтрации секретов и чтения произвольных файлов.

**Что сделать:** allowlist по ключам `summaries.json` + проверка
`path.resolve().is_relative_to(self.docs_dir.resolve())` + требование
расширения `.md`.

**Оценка:** S.

### BUG-01 — Ложный успех перевода; EN/UK могут получить русский ответ или пустую строку ✅

**Где:**
- `src/translator.py:105-108` — при исключении возвращает **исходный русский
  текст**; при пустом ответе API — `""` (через `openrouter_client.py:76-78`).
- `src/response_generator.py:259-272` — после вызова перевода **безусловно**
  ставит `metadata["translated_to"] = detected_language`, не проверяя результат.
- `src/main.py:794-816` — финальный шлюз считает ответ переведённым и
  **пропускает** повторный перевод; защита «осталась кириллица → извинение»
  находится внутри пропускаемой ветки и работает только для `en`.

**Суть:** один сбой LLM-перевода → англоязычный родитель получает русский
текст, строку «Превышено время ожидания ответа» или пустой ответ, а метаданные
утверждают успех. Для `uk` страховки нет вообще.

**Что сделать:** `translate()` возвращает `(text, ok)` или бросает исключение;
проверять непустоту и остаточную кириллицу; per-language fallback; не ставить
`translated_to` без проверки.

**Оценка:** S-M.

### BUG-02 — Ложные подтверждения действий пользователя ✅

**Где:**
- `src/simple_cta_blocker.py:24-33` — триггеры `['оплатил','заплатил',...]`,
  `['записался',...]` без учёта отрицаний.
- `src/completed_actions_handler.py:57-94` — то же.
- `src/completed_actions_handler.py:207-214` — грубое исключение вопросов
  (подстроки «как», «что»; >10 слов).
- `src/completed_actions_handler.py:242-252` + школьный контекст `:299-331` —
  контекст ищется в том числе в **ответах ассистента**, где почти всегда есть
  «Ukido»/«soft skills», поэтому фильтр фактически вакуумный.

**Примеры (статический разбор):**
- «Мы ещё **не** оплатили курс» → «Отлично! Оплата обрабатывается…».
- «Записались в бассейн» → «Ваша запись принята в Ukido…».
- «Заполнил форму в поликлинике» → «Спасибо! Мы получили вашу заявку…».

**Что сделать:** паттерны отрицаний; требовать школьный контекст **в самом
сообщении**; при сомнении уточнять, а не подтверждать.

**Оценка:** M.

### BUG-03 — Бессрочная блокировка CTA ✅

**Где:**
- `src/simple_cta_blocker.py:83` — `block_until_message = current_message_count + 7`
  (и `:94` — `+3`).
- `src/main.py:519` — `current_message_count = len(history_messages) + 1`.
- `src/history_manager.py:50-51`, `src/config.py:35` — история обрезается до 10
  сообщений, поэтому счётчик не превышает 11.

**Суть:** жёсткий отказ с 3-го хода (`count >= 5`) задаёт порог `>= 12`,
недостижимый никогда → CTA заблокированы до рестарта. `get_cta_frequency_modifier()`
(`:137-154`) навсегда снижает частоту до 0.2.

**Что сделать:** независимый от истории счётчик/таймстамп истечения; decay.

**Оценка:** S.

### BUG-04 — Ошибки API возвращаются как ответ и как шутка 🔎

**Где:**
- `src/openrouter_client.py:113-117` — при timeout/исключении возвращает
  человекочитаемые строки `"Превышено время ожидания ответа"`,
  `"Произошла ошибка при обработке запроса"`; при не-200 — `""` (`:76-78`).
- `src/response_generator.py:111-119` — любая непустая строка принимается как

- `src/zhvanetsky_humor.py:469-470` — любая непустая строка принимается как

**Суть:** родитель может получить как ответ или как «шутку» техническую строку
о таймауте. Ошибка неотличима от контента, нет метрики «API упал».

**Что сделать:** клиент бросает типизированные исключения; различать
transport-ошибку и валидный ответ.

**Оценка:** S.

### BUG-05 — Роутер создаёт невалидный «success» и фабрикует документы 🔎

**Где:** `src/router.py:198-201, 261-276, 279-281`.

- «Фикс» перемешивания `status`/`user_signal` ставит `status="success"`, но не
  создаёт `documents`; следующий шаг требует список документов и бросает
  `ValueError` → внешний `except` → `offtopic`.
- При упрямом `need_simplification` код принудительно делает `success` и
  синтезирует документы по **русским** подстрокам, иначе безусловно `faq.md`.
  Это противоречит собственному правилу промпта «нет документов → offtopic» и
  ведёт к ответам по нерелевантному FAQ.

**Что сделать:** не фабриковать `success`; валидировать согласованность
`status`/`documents`; при отсутствии документов возвращать `offtopic`.
P1, не спринт 0: ветка с `ValueError` → `offtopic` это fail-safe, а не падение.

**Оценка:** M.

### SEC-02 — Prompt injection и отсутствие структурной валидации ответа LLM 🔎

**Где:**
- Сырой текст пользователя и история вставляются в промпт роутера без
  разделителей и правила «текст пользователя — данные, не инструкции»
  (`src/router.py:497, 515, 589-592`).
- Не используется `response_format=json_object`, хотя клиент это умеет
  (`src/openrouter_client.py:51-52`); в few-shot формата есть `//`-комментарии и
  `"..."` (`src/router.py:920-928`), провоцирующие невалидный JSON; снятие
  ```-обёртки работает только для точного ` ```json ` (`:165-168`).
- Ретрай роутера принимается **без** валидации языка/сигнала/документов
  (`src/router.py:250-254`); `" ".join(decomposed_questions)` падает на
  не-строках (`:267-269`).
- Модель управляет `status`, `documents`, `user_signal`, `social_context`,
  влияющими на CTA, тон, юмор и обход рубрики.

**Суть:** пользователь влияет на коммерческую логику и выбор документов; в
связке с SEC-01 инъекция превращается в чтение файлов. Инъекции в истории
персистентны между ходами.

**Что сделать:** JSON-схема/валидация каждого поля, allowlist документов,
обёртка пользовательского текста, чистый формат few-shot, проверка типов.

**Оценка:** M.

### SEC-03 — Сырой HTML, обрезка ссылок, нет allowlist доменов ✅

**Где:** `src/response_generator.py:1223-1248`.

(`ukido.com.ua`, `*.beyondhorizon.dev`, `shao3d.github.io`), либо markdown/plain

### SEC-05 — Злоупотребления и неограниченный рост 🔎

- **Оракул существования контакта:** `/trial-signup` возвращает

- **Rate limit обходится ротацией `user_id`** (in-memory, per-ID); у

**Что сделать:** не раскрывать `updated` публично, лимиты по IP/глобальный
бюджет, eviction по TTL, лимит файлов во время работы.

**Оценка:** M.

## 5. P1 — надёжность, данные, эксплуатация

### OPS-01 — HEALTHCHECK не проверяет HTTP-статус ✅

`Dockerfile:47-48`: `httpx.get(...)` без `raise_for_status()` и без `sys.exit`.
5xx-ответ считается здоровым контейнером.

### OPS-02 — Откат релиза не откатывает зависимости 🔎

`ops/activate-release.sh:17-23` ставит новый `requirements.txt`, а при провале
health-check (`:48-60`) восстанавливает только код. Венв остаётся с новыми
пакетами → предыдущий релиз может не запуститься. `curl` без `--max-time`
(`:40`) может висеть; нет `flock`/проверки диска.

### OPS-03 — Персистентность: потеря данных, блокировка loop, сброс лимитов ✅/🔎

- Неатомарная запись `open(...,'w') + json.dump` (`persistence_manager.py:92-102`);
  повреждённый файл при загрузке **удаляется** (`:140-147`) — тихая потеря.
- Синхронная запись внутри async-хендлера на каждое сообщение (`main.py:832`).
- При реставрации теряются `metadata` (`:341`) → лимиты CTA и streak
  сбрасываются после рестарта.
- `SimpleCTABlocker` (отказы/действия) не персистится вовсе.
- `/clear_history` не вызывает `delete_state` (`main.py:1024-1028`) → данные
  возвращаются после рестарта.

## 8. Многоязычность: почему uk/en звучат неидеально и как починить

### 8.1 Диагноз

Основная схема — **«сгенерируй по-русски, потом переведи»**. Это даёт двойной
перевод (EN→RU замены в `_final_sanitize` перед переводом), дрейф смысла,
потерю абзацев и — главное — русские вкрапления уже **после** перевода.

### 8.2 Находки

- **LANG-01 — UK-детекция.** Роутер метит `uk` только по `і/ї/є/ґ`
  (`router.py:538-546`); «Дякую», «Добрий день», «Гаразд», «Добре» → `ru`.
  `resolve_language` (`localization.py:36-74`) не исправляет: ветка
  `raw=="ru" and not msg_has_cyrillic` не срабатывает на кириллице. Сессия
  залипает в `ru` → возможен русский юмор для украинца.
- **LANG-02 — UK-заготовки.** Словари только `ru`/`en`; `_pick` падает в `"ru"`
  (`localization.py:291-299`). `FAREWELL_ADDONS`/`THANKS_PREFIXES_SUCCESS`
  (`:234-252`) для uk не существуют, а `main.py` вклеивает их **после**
  перевода (`:640-654`), когда шлюз уже пропущен → русское «До свидания» в
  украинском ответе. `get_trial_signup_message("uk")` тоже вернёт русский
  (`:267-280`).
- **LANG-03 — RU-only эвристики:** question-words, ultra-short («а?»),
  acknowledgment, keyword-fallback, history-price (см. §7.1).
- **LANG-04 — Утечка метаданных.** `decomposed_questions` фильтруются только
  для `en` (`main.py:848-855`); для `uk` API вернёт русские вопросы.
- **LANG-05 — Юмор** RU-only + риски (см. §7.7).
- **LANG-06 — Соц/CTA-хейристики** RU+EN без uk (триггеры отказов, completed
  actions, CTA-маркеры), из-за чего в украинских диалогах не работают спейсинг
  CTA и детекция отказов.
- **LANG-07 — UI** жёстко `lang="en"`, без переключателя языка.

### 8.3 Рекомендация (уточнена 2026-09-11, см. §15.9)

Направление верное — «нативная генерация» — но как **оптимизация**, а не как
спринт. Сначала безопасная структурная фаза, затем нативную генерацию решает
живой замер, а не док.

**Почему не «сразу нативную генерацию»:**
- Русские эвристики живут на **выходе**: `offers_catalog` (CTA), инъекция
  контактов, `_final_sanitize` (EN/UK→RU), farewell/thanks-вставки — все ищут
  русские паттерны в тексте. При нативной генерации они перестают матчиться,
  то есть языковую привязку надо переносить на выход (сложнее), а не просто
  «убрать перевод».
- Naturalness: живой eval показал, что перевод сильной моделью уже
  естественный (en местами лучше нативного). Главные выгоды натива — минус
  один LLM-вызов и минус класс сбоев перевода (BUG-01 уже закрыт).
- Площадь поддержки: «генерация+перевод» = один русский промпт как источник
  правды; натив = три источника для 1300-строчного промпта.

**Фаза A — структурная (безопасно, ru не трогаем):**
1. **UK-детекция** по словесным маркерам, а не только `і/ї/є/ґ`.
2. **UK-словари заготовок** + перенос русских farewell/thanks-вставок до
   перевода (или язык-зависимость).
3. **UK few-shot в переводе** — паритет с en-промптом.
4. **Починить `_final_sanitize`** — не калечить выход (EN/UK→RU).
5. **UK в эвристиках** (refusals, completed actions, acknowledgment, fallback).
6. **Метаданные** декомпозиции — фильтровать/переводить и для uk.
Приёмка: в uk-ответах нет русских вкраплений, детекция не залипает, ru-выдача
не изменилась.

**Prerequisite (обе фазы):** golden-set 30-50 диалогов на язык + LLM-as-judge в
CI; тестировать естественность, а не только «нет кириллицы».

**Фаза B — нативная генерация (только по результатам замера):** один промпт с
языковым параметром + языковые few-shot; сравнить с Фазой A на golden-set и
выкатывать только при выигрыше. Каждый читатель выхода (CTA, санитайз, вставки)
обязан стать язык-зависимым.

**Юмор:** на сейчас выключен по умолчанию (`ZHVANETSKY_ENABLED=False`), код и
примеры сохранены. Переработка — позже, отдельным шагом.

## 12. Голосовой апгрейд: исследование и бюджетный план

### 12.1 Что показал рынок

**Native speech-to-speech:**
- **Gemini Live API** — 70+ языков, включая `ru`/`uk`; аудио `$3/M in` +
  `$12/M out` (native audio), ~$0.02/мин, **но** Google подтверждает
  перебиллинг накопленных аудио-токенов каждый ход → нужна context window
  compression; live-модель 2.5 native audio снимается 2026-12-13.
- **OpenAI gpt-realtime-mini** — audio `$10/M in` + `$20/M out` (~$0.03/мин);
  поддержка украинского не гарантирована.

**Open-source оркестрация:** `LiveKit Agents` (Apache-2.0) и `Pipecat` (BSD-2)
бесплатны; self-host на VPS = фиксированная стоимость; LiveKit Cloud ~$0.02/мин.
Reddit (r/AI_Agents): LiveKit+Realtime — <300 мс, но оркестрацию делаешь сам;
Vapi/Retell проще, но дороже/жёстче; совет — не привязываться к TTS-вендору.

**STT с украинским:**
- **Deepgram Nova-3** — монолингвально `uk`/`ru`; streaming $0.0048/мин
  (promo, list $0.0077).
- **ElevenLabs Scribe v2 Realtime** — $0.39/час ≈ $0.0065/мин, 90+ языков.
- **Google Chirp 3** — `ru-RU`/`uk-UA` GA.
- **Лайфхак под стек:** Gemini 2.5 Flash принимает аудио через ваш OpenRouter
  (`$1/M` аудио-токенов, ~32 ток/сек) ≈ **$0.001-0.002/мин**, без нового
  вендора и ключа.

**TTS с украинским:**
- **Azure Neural** — `$15-16/1M` символов ≈ $0.011/мин; `uk-UA-PolinaNeural`,
  `uk-UA-OstapNeural`; 0.5M символов/мес бесплатно.
- **Google Chirp 3 HD** — `$30/1M` ≈ $0.023/мин; `uk-UA`; low-latency streaming.
- **ElevenLabs Flash v2.5** — `$50/1M` ≈ $0.0375/мин; 32 языка (uk есть), ~75 мс.
- OpenRouter также отдаёт gpt-4o-mini-tts / Gemini TTS (один счёт).

**Browser Web Speech API** — «бесплатно», но Chrome/Google-бэкенд, uk ненадёжен,
вопросы приватности → только progressive enhancement.

### 12.2 Рекомендация: две фазы

**Фаза 1 — «голосовые заметки» (push-to-talk), 1-2 недели.**
`MediaRecorder` → `POST /voice` → STT (язык из сессии) → **существующий
текстовый пайплайн** → TTS → `{audio, text, metadata}`. Кэш TTS по хэшу
текста; аудио не хранить (или TTL 24ч).

Оценка на 500 сессий/мес × 3 мин:
- STT 1500 мин: Gemini/OpenRouter ≈ **$2-3**; Deepgram ≈ **$7-12**.
- TTS ~560k символов: Azure ≈ **$8**; Google ≈ **$17**; ElevenLabs ≈ **$28**.
- **Итого ≈ $11-40/мес** сверху, без новых вендоров (Gemini + Azure).

**Фаза 2 — дуплекс (barge-in), только если метрики покажут спрос.**
`LiveKit Agents` self-hosted + Gemini Live API (ru/uk) **или** Deepgram Flux +
Azure TTS. Python-гардрейлы в tool-calls, отдельный фича-флаг. Оценка: 1500
мин/мес ≈ **$30-75/мес** (API + опционально LiveKit Cloud).

**Приватность (обязательно):** голос — персональные данные; consent-чекбокс,
DPA провайдеров, не хранить записи, отразить в privacy policy.
